# 用户记忆和知识库

用户记忆：针对单个用户的个性化记忆。Agent 在与每位用户的交互中逐渐了解其偏好、习惯和需求，构建专属于该用户的知识模型。

知识库：面向所有用户共享的集体知识——比如一个行业的法规体系、一家公司内部的操作流程、一个技术领域的专业文档。

&nbsp;

## 用户记忆系统

记忆能力的评估：三层次框架

1. 第一层：基础回忆：要求 Agent 能够准确存储和检索用户直接提供的、结构化
   的、无歧义的信息。

2. 第二层：多会话检索：要求 Agent 在面对来自不同对象、不同时期的多段会话时，能检索出所有相关信息并推理判断。

3. 第三层：主动服务：要求系统综合来自多个会话、甚至很久以前的信息，提供具有预见性的主动帮助，从看似无关的记忆中发现深层联系。

&nbsp;

记忆评估的公开基准：

- LoCoMo（Long-term Conversational Memory，长期对话记忆）：构造了平均约 300 轮、最多 35 个会话的超长多轮对话，通过问答（细分为单跳、多跳、时间推理、开放域和对抗性问题）、事件摘要和多模态对话生成三类任务，考察模型对长程对话的记忆
  与理解能力。

&nbsp;

记忆的层次结构：

- 轨迹（Trajectory，短期记忆）：单次会话的完整原始记录，按时间顺序追加且不修改。
- 用户长期记忆：跨会话、跨实例的持久化存储，通常以键值对形式与特定用户 ID 绑定，其中存储着偏好设置、历史交互摘要和提取的知识点。

&nbsp;

用户记忆的四种存储格式：

1. Simple Notes：每条记忆是一个最小的、不可再分的事实。

2. Enhanced Notes：采用整体视角，将每条记忆保存为包含完整上下文的段落。

3. JSON Cards：采用三层嵌套结构（类别 → 子类别 → 键值对，如personal.contact.email、 work.position.title），模拟人类对信息的分类方式。

4. Advanced JSON Cards：每张卡片不仅记录事实，还加入信息来源的叙事背景（backstory）、主体身份（person）、与用户的关系（relationship）和时间戳。

关键且少量的数据（如用户偏好、关键人物关系）用 Advanced JSON Cards 以保证可
检索性； 大量且非关键的对话事实用 Simple Notes 以降低成本；多数生产系统采用混合模式——同一 Agent 内不同类别的信息走不同路径。

&nbsp;

更高级的知识表示形态：可执行代码。把用户状态改成带类型的可执行对象，并把规则写成普通函数，让“表示”和“推理”使用同一种可验证介质。

&nbsp;

记忆内容的类型：

- 工作记忆（Working Memory） ：用于处理当前任务的临时信息空间。
- 长期记忆：
  - 情景记忆（Episodic Memory）：关于具体事件和经历的记忆
  - 语义记忆（Semantic Memory）：从具体事件中抽象出的一般性知识。
  - 程序记忆（Procedural Memory）：关于行为模式和流程的记忆。
